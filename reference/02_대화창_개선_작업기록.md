# 2번 작업: 연속 요청과 이전 내역 조회가 가능한 대화창

작성일: 2026-10-21
브랜치: `feature/trendweave-reports`

## 작업 범위

사용자가 2번 작업 진행을 승인하여 대화창의 표시·입력·스크롤을 개선했다. ZARA 기반 흑백 스타일과 질문마다 4축을 분석하여 독립 보고서를 생성하는 현재 서비스 흐름을 유지한다.

일반 질문과 보고서 요청을 분류하거나 이전 대화 맥락을 LLM 입력에 반영하는 기능은 추가하지 않았다. 3번의 분석 단계 누적 표시 개선과 4번의 시즌 자동 판단·사람 검토도 진행하지 않았다.

이 문서는 2번 작업의 진행 상태와 결과를 기록한다. 1번의 새로고침 초기화는 그대로 유지한다.

## 확인한 문제

- 분석 이벤트와 완료 응답을 받을 때마다 대화창을 맨 아래로 이동시켜 이전 메시지를 읽기 어려웠다.
- 분석 중 입력창을 비활성화하여 다음 요청의 초안을 작성할 수 없었다.
- 첫 화면의 소개 영역과 고정 최소 높이를 대화 중에도 사용하여 작은 화면에서 입력창이 화면 아래로 밀릴 수 있었다.
- 한글 입력 중 Enter를 전송으로 처리할 수 있었고, 완료 후 다음 요청을 입력하는 흐름도 분명하지 않았다.

## 구현 내용

### 1. 대화 영역과 입력창 배치

`web_chat.html`에 Vue가 관리하는 `service-shell`을 두고 메시지가 있으면 `has-conversation` 클래스를 적용한다. 첫 요청 전에는 기존 소개 화면을 유지하고, 첫 요청부터는 소개 영역을 접어 대화 영역을 넓게 사용한다.

`static/trendweave.css`에서 대화 모드의 셸을 현재 뷰포트 높이에 맞추고, 상단 로고와 대화 헤더·입력창은 유지하면서 대화 내역만 스크롤되게 했다. flex 자식에 `min-height: 0`을 적용해 긴 보고서가 입력창을 밀어내지 않도록 했다. 모바일은 동적 뷰포트 높이(`100dvh`)와 좁은 여백을 사용한다.

사용자 메시지에는 `나` 라벨을 추가했다. 새 요청이 생겨도 이전 메시지와 보고서 객체를 대체하지 않고 기존 배열 뒤에 추가한다. 이전 보고서의 전체 보기와 PDF 다운로드는 각 보고서 ID를 계속 사용한다.

### 2. 다음 요청 작성과 전송

분석 중에도 입력창을 사용할 수 있게 하여 초안을 작성할 수 있도록 했다. 중복 실행 방지를 위해 현재 분석이 끝날 때까지 전송 버튼과 전송 함수의 실행 제한은 유지한다.

완료·실패 시 활성 작업의 연결을 정리하고 전송 제한을 해제한다. 초안은 그대로 유지하고 입력창에 포커스를 돌려준다. 이전 보고서 모달을 열어둔 경우에는 입력창으로 포커스를 빼앗지 않는다.

이전 작업의 늦은 응답이 다음 작업의 연결을 종료하지 않도록 활성 작업 객체를 확인한다. 완료된 보고서의 반복 조회만으로 대화창 위치나 입력 포커스를 다시 변경하지 않는다.

### 3. 이전 대화 스크롤 유지

현재 스크롤이 아래쪽에 있을 때만 새 진행 상태와 완료 결과를 따라 이동한다. 사용자가 위로 스크롤해 이전 내용을 읽는 중이면 해당 위치를 유지한다.

위쪽을 읽는 동안 새 내용이 들어오면 `최신 대화로 이동` 버튼을 표시한다. 버튼을 누르거나 사용자가 아래로 이동하면 버튼을 숨긴다. 사용자가 새 요청을 전송했을 때는 해당 새 메시지가 보이도록 맨 아래로 이동한다.

기존 분석 진행 기록 자체의 구성과 토글 동작은 변경하지 않았다.

### 4. 키보드 입력

- Enter: 요청 전송. 분석 중이면 추가 요청을 실행하지 않는다.
- Shift+Enter: 줄바꿈.
- 한글 IME 조합 확정 Enter: `isComposing` 및 조합 키 코드 229를 확인하여 의도치 않은 전송을 방지한다.

## 검증 결과

```bash
.venv/bin/python -m pytest -q --tb=short
node --check static/trendweave.js
```

전체 테스트 **20 passed**, JavaScript 구문 검사와 `git diff --check` 통과.

새 브라우저 검증은 1280×800과 390×844에서 실제 HTML·Vue·CSS·JavaScript를 실행했다. 보고서 API와 진행 이벤트는 테스트 응답을 사용하여 실제 외부 API 호출 없이 다음을 확인했다.

1. 첫 요청 이후에도 입력창이 화면 안에 유지된다.
2. 분석 중 다음 요청을 작성할 수 있으나 중복 전송은 제한된다.
3. 첫 보고서 완료 후 초안이 유지되고 두 번째 요청을 전송할 수 있다.
4. 사용자 메시지 2개와 보고서 카드 2개가 남아 있다.
5. 이전 내용을 읽는 중 진행 이벤트를 받아도 스크롤 위치가 바뀌지 않는다.
6. 최신 대화 이동 버튼으로 아래로 돌아갈 수 있다.
7. 두 번째 분석이 끝나도 열려 있는 첫 번째 보고서 모달의 포커스를 유지한다.
8. 이전 보고서의 PDF 다운로드가 첫 번째 작업 ID를 사용한다.
9. Shift+Enter와 한글 조합 확정으로 추가 요청을 보내지 않는다.
10. 새로고침 시 대화 초기화 동작도 기존대로 유지된다.

데스크톱·모바일 스크린샷을 직접 확인했으며, 브라우저 오류와 가로 넘침은 없었다. 검증용 스크린샷은 Git에서 제외된 `.artifacts/chat-conversation/1280.png`, `390.png`에 저장했다. 실제 외부 분석은 이번 작업에서 다시 실행하지 않았다.

## 사용자 확인 방법

1. 실행 중인 `http://localhost:8600`을 새로고침한다. 이전 JavaScript가 남아 있으면 강력 새로고침한다.
2. 예시 질문이나 자유 입력으로 첫 요청을 보낸다.
3. 분석 중 입력창에 다음 요청을 작성해 둔다.
4. 첫 보고서 완료 후 전송 버튼이나 Enter로 두 번째 요청을 보낸다.
5. 위로 스크롤하여 첫 메시지·보고서를 열어보고 새 진행 상태가 와도 읽던 위치가 유지되는지 확인한다.
6. `최신 대화로 이동`을 눌러 아래로 돌아온다.

프런트엔드 변경이므로 서버 재시작은 필요하지 않다. 사용자 확인을 받은 뒤 **3번: 분석 단계 누적 표시와 펼치기·접기 개선**을 진행한다.
