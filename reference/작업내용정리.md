# 주제 : 대화형 패션 트렌드 분석 AI Agent

핵심 목표 : 사용자의 질문을 분석하고, 필요한 패션 트렌드 정보를 수집하여 질문 목적에 맞는 맞춤형 분석 보고서를 생성하는 AI 서비스 개발

핵심 기능 :
런웨이, 컬러, 시장, 브랜드 4개 분야 중 사용자 질문에 적합한 항목을 선별하여 정보 검색 및 분석하여 맞춤형 보고서 생성

기존 서비스 : 4개 분야를 모두 조사하여 고정된 형식의 상품기획 보고서를 생성하는 방식

확장 서비스 : 사용자 질문에 따라 필요한 검색 분야를 선택적으로 실행하고, 분석 목적에 맞게 보고서의 내용과 형식을 동적으로 변경

e.g. 코디 추천 질문에는 컬러, 시장 트렌드를 중심으로 코디 추천서 작성, 브랜드 상품기획 질문에는 4개 분야를 종합한 상품기획 전략 보고서를 생성

구현 단계 : 기존 서비스인 '4개 분야를 모두 조사하여 고정된 형식의 상품기획 보고서 생성'을 우선적으로 하고, 해당 기능이 구현될 경우 추가적으로 질문별 적합한 항목 선별해 정보 검색 및 보고서 생성해주는 기능을 확장한다.

## 1. 우선 순위 기능

기존에 구현한 런웨이, 컬러, 시장, 브랜드 4개 분야의 트렌드 분석 기능을 웹서비스와 연결해 보세요.

사용자가 웹 화면에서 분석 요청
FastAPI 백엔드에서 요청 수신
기존 패션 트렌드 분석 로직 실행
4개 분야별 정보 검색 및 분석
분석 결과를 상품기획 보고서 형태로 생성
생성된 보고서를 웹 화면에 표시
우선 이 과정이 처음부터 끝까지 정상적으로 동작하도록 구현하는 것이 목표입니다.

## 2. 시간이 남으면 확장할 기능

기본 기능이 완성된 이후 기존 전달해준 질문 유형별 선택적 검색 기능을 추가하면 됩니다.

예를 들어,

코디 추천 → 컬러·시장 트렌드 중심 분석
브랜드 상품기획 → 런웨이/컬러/시장/브랜드 종합 분석

LangGraph를 활용하여 사용자 질문을 분류하고, 필요한 분석 기능만 선택적으로 실행하도록 구현하면 AI Agent의 기술적 특징도 보여줄 수 있습니다.
다만 이 기능은 추가 구현 목표로 두고, 기본 웹서비스 완성을 우선해 주세요.

### 추가할 내용

```
### 확장 기능: 질문 기반 선택적 리서치 및 동적 보고서 생성

**목표**

기존의 4개 분야 전체 검색 및 고정형 상품기획 보고서 생성 방식을 개선하여, 사용자의 질문에 따라 검색 분야와 보고서 구성이 달라지는 대화형 AI Agent 구현

**주요 기능**

1. **사용자 질문 분류**
   - LLM을 활용하여 질문의 분석 목적, 검색 분야, 보고서 유형을 판단
   - 분류 결과를 Structured Output으로 반환하고 LangGraph State에 저장

2. **선택적 리서치 실행**
   - 런웨이, 컬러, 시장, 브랜드 4개 분야 중 질문에 필요한 분야를 선택
   - LangGraph의 조건부 분기와 Send를 활용하여 선택한 분야만 병렬 조사
   - 기존 검색·평가·재검색·정보 추출 로직 재사용

3. **동적 보고서 생성**
   - 질문의 분석 목적에 따라 보고서의 구성과 분석 관점 변경
   - 트렌드 분석서, 코디 추천서, 상품기획 전략 보고서, 브랜드 비교 보고서 등 생성
   - 보고서 유형별 필수 항목 및 근거 검증

4. **분석 방향 확인 및 수정**
   - AI가 제안한 검색 분야와 보고서 유형을 사용자에게 표시
   - 사용자가 분석 방향을 확인하거나 수정한 후 리서치 진행

**처리 흐름**

사용자 질문 → LLM 질문 분류 → 분석 방향 확인 → 선택적 리서치 → 결과 통합 → 유형별 보고서 생성 → 결과 검증 → 웹 화면 출력
```

## 3. day2 개발 시 확인할 사항

① 기존 패션 분석 코드가 정상 실행되는지 확인

## 5. 구현된 TrendWeave 실행 방법 (2026-10-21 추가)

### 5.1 현재 PC에서 바로 실행하기

프로젝트 폴더에서 터미널을 열고 다음 명령을 실행합니다. 앞선 구현 과정에서 현재 PC의 가상환경, 패키지, PDF용 Chromium 설치와 실제 API 연동을 확인했습니다. `.env`에 등록된 키를 그대로 사용한다면 설치 단계를 반복할 필요가 없습니다.

```bash
cd /Users/minchae/Desktop/workspace/SKALA/working/22_ai_capstone/hw/all_total_vue_student
./run.sh
```

터미널을 실행 상태로 유지하고 브라우저에서 **http://localhost:8600** 에 접속합니다. 실행 스크립트가 백엔드(8100)와 웹 화면(8600)을 함께 실행합니다.

### 5.2 새 환경에서 최초 설치하기

다른 PC나 새로 받은 프로젝트에서 실행할 때만 프로젝트 최상위 폴더에서 다음 명령을 수행합니다. Python 3.11 이상을 사용합니다.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
```

프로젝트 최상위에 `.env`가 없다면 `.env.example`을 복사합니다.

```bash
cp .env.example .env
```

**이미 `.env`가 있으면 복사 명령으로 덮어쓰지 말고**, 기존 파일에서 아래 항목을 확인하거나 추가합니다.

```dotenv
SERVICE_MODE=trendweave
GOOGLE_API_KEY=본인의_Gemini_API_키
TAVILY_API_KEY=본인의_Tavily_API_키
TREND_MODEL=gemini-3.1-flash-lite
TREND_REQUESTS_PER_SECOND=0.25
TREND_MAX_WORKERS=1
TREND_SEARCH_TIMEOUT=30
```

`GOOGLE_API_KEY`와 `TAVILY_API_KEY`에는 실제 사용할 키를 입력해야 합니다. 두 키가 모두 필요하며, 기존의 `OPENAI_API_KEY`만으로는 현재 패션 분석을 실행할 수 없습니다. 설정한 뒤 `./run.sh`를 실행합니다.

### 5.3 화면에서 기능 확인하기

1. 브라우저에서 `http://localhost:8600`을 엽니다.
2. **예시 질문으로 시작** 버튼을 누르거나 상품기획 요청을 입력합니다. 시즌을 먼저 선택할 필요는 없습니다. 브랜드는 ZARA로 고정되어 있습니다.
3. LLM이 요청 시각(한국시간)과 질문을 바탕으로 시즌과 보고서 방향을 제안합니다. 질문에 시즌을 명시했다면 이를 우선합니다.
4. **분석 방향을 확인해주세요** 카드에서 시즌·브랜드·요청·보고서 방향과 제안 이유를 검토합니다. 시즌·요청·방향을 수정할 수 있습니다.
5. **확인하고 보고서 생성**을 눌러야 실제 분석을 시작합니다. **생성 취소**를 누르면 보고서를 생성하지 않습니다.
6. 누적 **분석 과정**에서 런웨이·컬러·시장·브랜드 조사와 전략 작성·검토를 확인합니다. 펼치기·접기로 표시를 조절할 수 있으며 실제 분석은 약 2~4분 이상 걸릴 수 있습니다.
7. 완료 카드에서 요약과 자료 충분도를 확인하고, **전체 보고서 보기** 또는 **PDF 다운로드**를 사용합니다.

입력창에 아래와 같은 요청을 직접 작성하고 전송 버튼을 눌러도 됩니다.

> 데님 상품군 중심으로, 여름에도 입기 좋은 가벼운 소재 위주로 기획해줘.

자유 입력도 먼저 제안과 사용자 확인을 거친 뒤 승인하면 4개 분야 전체를 조사합니다. 질문에 따라 분야를 선택하는 확장 기능은 구현하지 않았습니다. 새로고침하면 이전 대화·보고서 카드·입력 내용이 초기화되어 새로운 대화로 시작합니다. 진행 중인 서버 분석과 저장된 보고서는 유지하지만, 이전 작업을 화면에서 자동으로 다시 연결하지는 않습니다.

### 5.4 종료 및 문제 해결

- **종료:** 실행한 터미널에서 `Control + C`를 누르면 두 서버가 함께 종료됩니다.
- **가상환경이 없다는 안내:** 5.2의 가상환경 생성과 패키지 설치를 수행합니다.
- **API 키가 없다는 안내:** 프로젝트 최상위 `.env`에 두 키가 모두 입력되어 있는지 확인한 뒤 서버를 다시 실행합니다.
- **8100 또는 8600 포트 사용 중:** 기존에 서버를 실행한 터미널에서 `Control + C`로 종료한 뒤 다시 실행합니다. 터미널을 추가로 열어 같은 서버를 중복 실행하지 않습니다.
- **방향 제안 실패:** 모델 설정·호출 한도·네트워크를 확인하고 제안 다시 받기를 누릅니다. 실패한 제안만으로 보고서가 생성되지는 않습니다.
- **분석 실패:** 키의 유효성, Gemini 모델 사용 가능 여부, API 호출 한도와 네트워크를 확인하고 화면의 재시도 버튼으로 다시 요청합니다.
- **PDF 다운로드 실패:** `.venv/bin/python -m playwright install chromium`을 실행한 뒤 다운로드를 다시 누릅니다. 보고서 분석을 새로 실행할 필요는 없습니다.
- **서버를 종료한 뒤 미완료 분석:** 서버 재시작 시 실패 상태로 정리되므로 다시 요청합니다. 완료된 보고서는 `reports.db`에 보존됩니다.

서버 상태를 별도로 확인하려면 실행 중 브라우저에서 `http://localhost:8100/health`를 엽니다. `analysis_ready`가 `true`이면 분석 도구 설정이 준비된 상태입니다.
