# 3번 작업: 분석 과정 누적 표시와 펼치기·접기

작성일: 2026-10-21
브랜치: `feature/trendweave-reports`

## 작업 범위

사용자의 3번 작업 진행 승인에 따라 분석 과정을 시간순으로 누적하고 보고서마다 펼치거나 접을 수 있도록 개선했다. ZARA 고정 4축 분석과 보고서·PDF 생성 흐름, 1번의 새로고침 초기화, 2번의 대화창·스크롤 동작은 유지한다.

4번인 LLM 시즌 자동 판단과 사람 검토 단계는 구현하지 않았다.

## 기존 상태와 변경 방향

이전 화면은 가장 최근 이벤트를 한 줄로 표시하고, 누적 이벤트는 기본적으로 접힌 `details`의 단순 목록 안에 두었다. 이번에는 **분석 과정을 기본으로 펼쳐 보여주는 누적 목록**으로 바꾸고, 기록이 많아지면 명시적인 버튼으로 접을 수 있게 했다.

## 구현 내용

### 1. 누적 목록

각 보고서 카드 안에 독립적인 분석 과정 영역을 추가했다.

- 요청 정리, 검색 계획, 자료 검색, 문서 평가, 재검색 계획, 신호 추출, 전략 작성, 전략 검토, 보고서 작성, 완료·실패 등을 한글 단계 이름으로 표시한다.
- 서버 이벤트 ID 순서대로 번호를 붙이고 해당 분야(런웨이·컬러·시장·브랜드)와 실제 이벤트 메시지를 함께 표시한다.
- 이전 메시지를 덮어쓰지 않고 새 기록을 추가한다. 재검색과 재작성도 별도 기록으로 남긴다.
- 목록의 높이를 데스크톱 240px, 모바일 180px로 제한하고 그 안에서 이전 기록을 스크롤할 수 있게 했다. 기록을 잘라내지는 않는다.
- 목록의 아래쪽을 보고 있으면 새 기록을 따라가고, 과거 기록을 읽고 있으면 목록 안의 스크롤 위치를 유지한다.

기존의 가장 최근 단계 한 줄 표시도 분석 중에는 유지하여 현재 상태를 빠르게 확인할 수 있게 했다.

### 2. 보고서별 펼치기·접기

- 기본값은 펼침이다. 아직 이벤트가 없으면 준비 안내를 표시한다.
- `분석 과정 · N개 기록` 옆의 `접기 −` 또는 `펼치기 +` 버튼으로 전환한다.
- 접힌 상태에서도 기록과 개수는 계속 누적한다. 새 이벤트가 와도 사용자가 접어둔 상태를 강제로 펼치지 않는다.
- 다시 펼치면 누적된 기록을 표시한다. 완료 또는 실패한 뒤에도 같은 보고서 카드에서 다시 확인할 수 있다.
- 다른 보고서의 펼침 상태와 기록은 서로 영향을 주지 않는다.
- 버튼에 `aria-expanded`, `aria-controls`를 적용하고 Enter·Space 키로도 사용할 수 있게 했다. 기록 목록은 키보드로 스크롤할 수 있다.

### 3. 중복 방지와 누락 복구

프런트엔드의 이벤트 처리를 공통 병합 함수로 정리했다. 이벤트 ID로 중복을 제거하고 ID 순서로 정렬한다. 재연결 때 같은 이벤트를 다시 받아도 기록 개수가 늘어나지 않으며, 늦게 도착한 앞 순번의 이벤트도 버리지 않는다.

기존에는 polling이 완료 상태를 먼저 관찰하면 SSE 연결이 닫히면서 아직 받지 못한 기록이 화면에 빠질 수 있었다. 이를 해결하기 위해 `GET /reports/{report_id}` 응답에 DB에 저장된 이벤트 목록과 ID를 추가했다. 진행 조회·재연결·최종 조회 시 이 기록을 SSE 기록과 병합한다.

따라서 완료 또는 실패를 먼저 확인하더라도 이전 단계와 마지막 기록을 복구할 수 있다. 새 분석 작업을 생성하거나 외부 API를 추가 호출하는 처리는 아니다. DB 스키마와 분석 그래프는 변경하지 않았다.

## 검증 결과

```bash
.venv/bin/python -m pytest -q --tb=short
node --check static/trendweave.js
```

전체 자동 테스트 **22 passed**. JavaScript 구문 검사와 `git diff --check`도 통과했다.

새 브라우저 테스트는 1280×800과 390×844에서 실제 화면 코드를 실행하고 API·진행 이벤트에 테스트 응답을 사용했다. 외부 LLM·검색 API와 실제 보고서 DB는 사용하지 않았다.

확인 사항:

1. 시작 직후 기본 펼침과 준비 안내 표시
2. 여러 분야와 단계의 이전 기록 유지 및 순서대로 누적
3. 접힌 상태에서 새 기록이 추가되어도 접힘 유지 및 개수 갱신
4. 버튼 클릭·Enter·Space로 펼치기와 접기
5. 중복 이벤트를 다시 받아도 중복 표시 없음
6. 뒤늦게 도착한 앞 순번 기록을 올바른 위치에 병합
7. 많은 기록을 내부 스크롤로 확인하고 읽던 위치 유지
8. SSE에서 누락된 최종 기록을 저장 목록으로 복구
9. 완료·실패 뒤에도 기록 확인 가능
10. 보고서별 기록 및 펼침 상태 분리
11. 기존 대화창·새로고침 초기화·보고서·PDF 회귀 테스트 유지

데스크톱·모바일 스크린샷을 직접 확인했다. 브라우저 오류와 가로 넘침은 없었다. 로컬 검증 이미지는 Git에서 제외된 `.artifacts/analysis-history/1280.png`, `390.png`에 저장했다.

## 사용자 확인 방법

이번에는 보고서 조회 API도 변경했으므로 기존 `./run.sh` 터미널에서 `Control + C`를 누른 뒤 `./run.sh`를 다시 실행한다. 웹 화면 `http://localhost:8600`도 새로고침한다.

1. 새 분석 요청을 전송한다.
2. `분석 과정`에 검색·평가 등의 기록이 순서대로 쌓이는지 확인한다.
3. `접기`를 눌러 목록을 숨기고, 분석이 진행될 때 기록 개수가 증가하는지 확인한다.
4. `펼치기`를 눌러 이전 기록까지 확인한다. 기록이 많으면 목록 내부를 스크롤한다.
5. 완료 후에도 같은 보고서에서 기록을 다시 펼쳐 본다.

새로고침하면 1번 작업에서 정한 대로 대화가 초기화된다. 사용자 확인을 받은 뒤에만 **4번: 시즌 자동 판단 및 사람 검토**를 진행한다.
