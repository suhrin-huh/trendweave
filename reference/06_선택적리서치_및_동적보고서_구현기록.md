# 선택적 리서치 및 동적 보고서 구현 기록

작성일: 2026-10-21  
기준: [05 설계서](./05_질문기반_선택적리서치_및_동적보고서_설계.md)

## 구현 결과

- **패션 관련성 선행 판단:** 비패션은 고정 지원 범위 안내, 모호하거나 혼합된 요청은 질문 보완 안내로 종료한다. 이때 승인 가능한 제안·작업을 생성하지 않고 검색·보고서 작성을 실행하지 않는다. 분류 모델 오류는 비패션 판정과 구분하여 재시도 가능한 오류로 반환한다.
- **유형별 분석 계획:** 코디 추천·트렌드 분석·ZARA 상품기획을 지원한다. 계획에는 시즌, 목적, 유형, 조사 분야, 선택 이유, 가정을 저장한다.
- **사용자 수정·승인:** 유형과 분야를 수정할 수 있다. 코디는 컬러·시장, 상품기획은 네 분야가 필수다. 질문·시즌·방향을 수정하면 제안을 다시 받아 관련성을 재확인해야 한다.
- **서버 검증:** 저장된 패션 판정과 원문·시즌·방향을 승인 시 대조한다. 클라이언트의 관련성 판정 주장은 받지 않는다. 취소·중복 승인 방지와 대기열 제한을 유지한다.
- **선택적 실행:** 선택 분야에 대해서만 검색 계획과 `Send`를 생성한다. 기존 검색·평가·재검색·추출 로직을 재사용하고 합류 후 작성 단계로 진행한다.
- **보고서 3종:** 기존 상품기획 모델을 유지하면서 코디·트렌드의 구조화 모델, 작성·검토·Markdown 생성을 추가했다. 각 결과에 근거 ID를 연결하고 공통 웹 렌더링·PDF 변환을 재사용한다.
- **부분 실패와 품질 표시:** 분야별 성공·자료 부족·실패·미선택을 구분한다. 전체 유효 근거가 없으면 작업을 실패 처리한다. 결과 품질은 `passed`, `limited`, `review_required`로 표시하며 처리 완료와 구분한다.

브랜드 비교와 다른 브랜드 조사는 설계서의 후속 범위로 유지한다. 일반 코디·트렌드에서 브랜드 조사를 하지 않으면 ZARA를 제목·PDF 파일명에 자동으로 붙이지 않는다.

## 주요 변경 위치

| 위치 | 역할 |
|---|---|
| `agent/trendweave/review.py` | 관련성 판단, 지원 범위, 계획 제안, 분야 조합 검증 |
| `agent/trendweave/schemas.py`, `state.py` | 계획·보고서 모델과 실행·품질 상태 |
| `agent/trendweave/engine.py` | 선택 분야 계획·분배, 기존 리서치 재사용, 유형별 작성 분기 |
| `agent/trendweave/dynamic_reports.py` | 코디·트렌드 작성, 근거·형식 검증, 품질 계산, 보고서 구성 |
| `services/preview_service.py`, `report_routes.py`, `report_service.py` | 상태별 응답, 승인 검증, 계획 전달, 저장·조회·PDF 연결 |
| `web_chat.html`, `static/trendweave.js`, `trendweave.css` | 범위 안내, 유형·분야 선택, 재제안, 결과 표시 |

기존 DB 테이블은 JSON 필드로 확장 정보를 저장하므로 테이블 변경은 필요 없다. 과거 완료 보고서의 조회·PDF는 기존 결과로 유지한다. 새 관련성 판정이 없는 과거 미승인 제안은 다시 제안받아야 한다.

- 전체 근거 부족, 부분 실패, 잘못된 근거 ID, 검토 모델 실패, 재작성 한도 도달을 검증했다.
- 실제 Chromium에서 데스크톱·모바일 승인 화면과 보고서 3종의 한글 PDF를 검증했다.

### 실제 외부 API 검증의 제한

설정된 Gemini 모델에 실제 호출을 시도했으나 **503 UNAVAILABLE / 모델 수요 증가** 응답으로 관련성 판단 단계에서 중단됐다. 재시도도 완료하지 못했으며, 이번 변경의 실제 Gemini·Tavily 보고서 생성 성공은 아직 확인하지 못했다. 위 56개 테스트 통과가 실제 API 검증 성공을 뜻하지는 않는다.

모델이 사용 가능한 시점에 아래 스크립트로 비패션 차단과 보고서 유형별 실제 연동을 다시 확인할 수 있다. 모델 변경이나 키 변경은 하지 않았다.

```bash
.venv/bin/python scripts/verify_selective_live.py
```

성공한 유형의 보고서와 실행 요약은 `.artifacts/selective-live/`에 저장한다. LLM 기반 관련성·근거 적합성 판단의 오분류 가능성은 남아 있다.

## 화면에서 확인하기

실행 중인 기존 서버가 있다면 종료하고 다시 실행한다.

```bash
./run.sh
```

`http://localhost:8600`에서 아래 질문을 입력한다.

| 질문 | 기대 동작 |
|---|---|
| 파이썬으로 계산기 코드를 작성해줘 | 패션 지원 범위 안내, 승인 카드 없음 |
| 여름 출근용 데님 코디를 추천해줘 | 코디 유형, 컬러·시장 중심 제안 |
| 2027 S/S 의류 컬러 트렌드만 분석해줘 | 트렌드 유형, 컬러 조사 제안 |
| ZARA의 다음 시즌 데님 상품기획 방향을 제안해줘 | 상품기획 유형, 4개 분야 제안 |

보고서 유형·분야를 확인한 뒤 승인한다. 질문·시즌·방향을 고쳤다면 **제안 다시 받기**를 먼저 누른다. Gemini가 계속 503을 반환하면 실제 제안 단계에서 오류가 표시되며 보고서는 생성되지 않는다.
